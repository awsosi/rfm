PIM - Product Information Manager Signalling

Second, independent signalling target alongside ROSAPI. Authenticates with a static X-API-TOKEN header. Fires on PUSH, PULL and UPDATE. Every notification is queued and retried until PIM accepts it; its state shows next to the operation in the history.

Master switch for all PIM notifications
PIM API base URL
Path appended to the base URL
HTTP method for PIM signal requests
Sent as the X-API-TOKEN request header
HTTP request timeout for PIM calls

Event Types

Each operation can be toggled separately and reports its own eventType.

Payload Template

Request body sent to PIM. Placeholders: {files} (raw JSON array of top-level filenames), {catalog_name}, {event_type}, {tg_id} (product tgId, Polka27.elementy.grup_nazwe), {operation_id}, {username}, {source_path}, {dest_path}. Every placeholder except {files} and {operation_id} is JSON-escaped.

{tg_id} comes from RFM_ValidateProductName for the pushed catalog (e.g. TORBA HB0788 FA0542-910 SILVER → TORBA HB0788 FA0542). It needs the web service URL and API key under Catalog & Content Validation, even while that gate is switched off. An event whose tgId cannot be resolved is retried, not sent without it.

Delivery & Retries

A failed attempt (network error, timeout, non-2xx answer, missing setting) is retried with exponential backoff: the base delay doubles after every failure up to the maximum delay. Notifications of one catalog are delivered in order. Settings changed here also apply to notifications already waiting.

The notification is then marked failed; users can send it again from the operation details. 0 retries forever.

Notification Queue

Notifications waiting to be sent or retrying. Stopping them marks them stopped: they are kept in the operation history, are not retried, and can be sent again one by one from the operation details. A single notification can also be stopped there.

Gates applied before every PUSH and UPDATE. Both are hard blocks: a failing catalog cannot be pushed.

Catalog Name Validation (PolkaSQL)

Checks the folder name against Polka27.elementy.grup_nazwe_kolor via the RFM_ValidateProductName web service, and offers the closest matches on a miss. The same service returns the product's tgId (grup_nazwe) for PIM, so its URL and API key are needed whenever PIM sends {tg_id}.

Refuse PUSH/UPDATE when the catalog name matches no product
Full URL of the PolkaSQL Raw web service
Passed as the ApiKey query parameter
How many alternative names to offer when the name does not match
Off by default (fail closed). While off, a PolkaSQL outage blocks every PUSH and UPDATE. Turn on only for the duration of an outage.

Directory Content Validation

Requires a minimum number of genuine image files. Non-image files do not count toward the minimum but are still sent to PIM.

Comma-separated list, without dots
Check magic bytes as well as the extension, so a renamed file cannot pass as an image. A mismatch blocks the operation.
Every file must be named <number>.<extension> (e.g. 3.png), optionally with one of the suffixes below (e.g. 3_ai.png). Any other name blocks the operation. Files matching Ignored File Masks are not checked.
Comma-separated suffixes accepted between the number and the extension, so _ai lets 1_ai.png through next to 1.png. Case-insensitive (_ai, _AI, _Ai, _aI all match). Letters, digits, _ and - only; leave empty to accept numbers alone.

UPDATE Behaviour

Off by default. When on, in-place changes made in PATH_B are replayed against the archive copy in PATH_C. Best-effort: a mirror failure is logged but does not fail the operation.

Image Host Sync Verification

After a PUSH, checks one URL per image file until the image host serves every image. Progress shows next to the PUSH in the operation history (waiting for PIM, n of m served, synced, timed out, cancelled by PULL). An UPDATE re-checks the files it added, replaced or renamed. A file counts as served on HTTP 200 with an image content type and a non-empty body.

Off by default. Applies to PUSH operations completed while it is on.
Placeholders, URL-encoded: {catalog_name}, {file} (e.g. 1.png), {tg_id}. Files checked are the catalog's top-level files with an image extension (Allowed Image Extensions above).
When PIM signalling is on, the clock starts when PIM accepts the notification, so a PIM outage is not reported as a sync timeout.
Only files not yet served are requested again
Images still missing after this long are reported as timed out. Users can start checking again from the operation details.
Adds a unique rfm_sync query parameter to every request. The image CDN caches 404 answers for an hour and was seen serving an empty cached 200 for a missing file; keep on unless the host rejects query parameters.

Active Checks

Checks waiting for PIM or polling the image host. Stopping them marks them stopped: they are kept in the operation history and can be started again one by one from the operation details. Works while verification is switched off.
